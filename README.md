# B站首页低质内容过滤

Chrome 里的 Tampermonkey 用户脚本（`bilibili-filter.user.js`），用于隐藏 B 站首页推荐流中的
短时长大字报 / 营销号视频。

五层判定：直播 → 广告 → 主题屏蔽（47 类）→ 硬时长下限 → 文案指纹。
主题命中即拦，不看时长；其余按信号累计打分。

## 安装

需要 Chrome（Safari 未覆盖）和 [Tampermonkey](https://www.tampermonkey.net/)。
Chrome 扩展形态（`chrome-ext/`）已废弃，只维护用户脚本。

### 装给自己用（本机开发版）

```bash
./deploy.sh
```

它会拉起本地服务（`serve.py`，端口 8899），打开 Tampermonkey 的安装页，
你在那个标签页点一下 **Update** 即可。装好后刷新 B 站。

### 装给别人用（分发包）

```bash
./make-dist.sh
```

产物在 `releases/bilibili-filter-v4.50.0-dist.user.js`。它比个人版少两行
`@updateURL` / `@downloadURL` —— 否则对方会被指向你本机的 8899 端口，
更新永远失败，还可能有拉到别的东西的风险。

把文件发给对方，拖进 Chrome 窗口，Tampermonkey 会弹出安装页。

**`releases/` 里只放 `-dist` 后缀的包。** 个人版 `.user.js` 快照带着
`@updateURL http://127.0.0.1:8899`，对方装上去后 Tampermonkey 会反复
去连他自己本机的 8899 端口：更新永远失败，万一那头有别的服务还可能
拉到不明内容。所以那类文件已从仓库排除（`.gitignore` 里有说明）。

历史版本按 `-dist` 取，校验值见 `releases/SHA256SUMS.txt`：

```bash
shasum -a 256 -c releases/SHA256SUMS.txt
```

### 装完怎么确认

右下角出现徽章 `🛡 v4.50.0 aggressive 拦 N / 扫 M`，滚动时数字增长。点它有拦截明细。
没出现就是没生效，看下面的「调试工具」。

### 从旧版升级

`@name` 改了，Tampermonkey 会把新脚本当成**另一个脚本**。装完请到扩展面板把旧的
「Bilibili 低质营销号过滤」删掉 —— 两个同时跑会重复隐藏，日志也对不上。

黑名单和白名单存在 `localStorage`（按 `bilibili.com` 域存），**不会丢**。

## 五层过滤
脚本做五件不同的事，**判定顺序是：关注/白名单 → 直播 → 广告 → 主题 → 时长 → 质量**。

1. **直播**：首页的直播卡片，按链接域名识别（`live.bilibili.com`），整块移除。
2. **广告**：平台插进推荐流的广告位，按接口字段和 DOM 标记识别，整块移除。
3. **主题屏蔽**：不看这个话题（共 **47 类**，可逐个关）。命中即拦，
   **完全不看时长和文案分数** —— 一条拍得很好的情感视频照样不要。
   常见的有：两性对立 / 情感关系（含**所有带「婚」字的**）/ **原生家庭** /
   **厚黑权术** / 考公考研 / 车祸事故 / 搞笑段子 / 猫meme / 外网搬运 /
   外国人爽文 / 升学导师 / 清史内容 / 锐评排名 / 现象议论体 / AI剧情短剧 /
   AI模型账号 / 死亡猎奇 / 奥特曼 / **网文 IP**（斗罗大陆 / 剑来 等）/
   **抖音内容** / **流行歌曲** / **氛围音 / 助眠** / **牢A 梗号** /
   **外国猎奇** / **商业大佬叙事** / **外国政要** / **COS 角色扮演** /
   **主播** 等。完整清单见下面的 `CONFIG.topics`。
4. **硬时长下限**：不足 180 秒一律隐藏，不看标题。纯长度偏好，
   连央视 45s 短新闻也删。
5. **质量过滤**：话题没问题、时长也够，但内容是大字报 / 营销号。走下面的指纹打分。

### 直播（4.33.0）

开关 `CONFIG.hideLive`（默认 **true**）。隐藏首页的直播卡片。

**这条规则的坑不在判据，而在入口。** 原来的实现是：

```js
const isVideo = goto === 'av' || goto === 'ogv' || goto === 'bangumi';
if (CONFIG.hideLive && !isVideo) { /* 隐藏 */ }
```

两个问题：

1. **`scan()` 只抓 `/video/BV` 与 `/video/av`**。直播卡的链接指向
   `live.bilibili.com`，**根本不在扫描范围内** —— 开关开着也删不掉。
2. **`!isVideo` 是近似**。把默认值改成 true 之后，`badge` / `loading` /
   `download` 这些垃圾值也会被当成「非视频流」拦掉（实测 7 条断言全红）。

现在：

- 新增 `FEED_LINK_SEL`（视频 + 直播），`scan()` 与 `linkCount()` 都用它。
  `linkCount` 必须一起改 —— 否则「只含直播链接的列表容器」会被当成单张卡片，
  隐藏它就清空了整片信息流。
- `findCard()` 对直播卡放宽「必须有时长」的条件。直播没有时长，
  按原逻辑会被判定为「不是卡片」而跳过。
- 判定改为精确匹配 `goto === 'live' || 'live_room'`，删掉 `!isVideo` 那段。
- DOM 层判据是 `a[href*="live.bilibili.com/"]`，不依赖 `goto` ——
  接口层 hook 从未触发过，只有 DOM 层可靠。

**直播卡不走时长门**：它们没有时长，若走 `d > 0` 的分支会落到
「时长未知，跳过」而漏网。所以直播判定排在 `decide()` 之前。

验证：`node live-test.js`（配置、源码入口、接口层、7 种垃圾 goto 不被牵连、
DOM 层混排、白名单与黑名单优先级、开关、0s 直播）。

### 广告（4.26.0）

开关 `CONFIG.hideAds`（默认 **true**）。

**判据只用结构标记，不看标题文字。** 这是刻意的：「中国广告业四十年」
「广告的商业模式」是正常内容，按词匹配会成片误杀。

接口层（`isAdItem`），整值匹配，不用子串：

- `goto` / `card_goto` / `card_type` 等于 `ad` / `cm` / `ad_av` / `ad_web` /
  `ad_live` / `ad_banner` / `commercial` / `promo`

用整值而不是 `/ad/`：`badge`、`loading`、`download`、`header` 里都有 `ad`，
子串匹配会把正常卡片删掉。

DOM 层（`cardIsAd`）：

- 属性：`[data-ad-id]`、`[data-ad]`
- 状态类：`.is-ad`、`[class*="--ad"]`、`.ad-tag`、`.ad-badge`
- 「广告」角标文字：只在角标元素内取文本，且必须**精确等于**
  `广告 / 赞助 / 推广 / AD`。「广告投放技巧」这种不命中。

刻意避开裸 `[class*="ad"]` —— 它会咬到 `download` / `loading` / `badge` / `header`，
这些 class 在正常卡片里到处都是。

**首页 banner**（`cleanAdBanners`）：`[data-ad-id]`、`[data-ad-req-id]`、
`[class*="ad-banner"]`、`[class*="banner-ad"]`、`.bili-feed-banner__ad`、`.ad-report`。

两道额外保护：

1. **二次复核**（`bannerIsAd`）：选择器命中后还要确认元素真的带广告属性/类。
   实测踩过 —— 某些选择器实现对复杂组合选择器会返回整批节点，
   不复核就会把整片信息流当 banner 清掉。
2. **容器保护**：含视频链接超过 `MAX_LINKS_PER_CARD` 的区域跳过。

它在 `scan()` 里执行并节流 500ms，所以 SPA 切页后重新出现的 banner 也会被清。

**优先级**：广告排在白名单之后 —— 你手动 ✅ 放行的 UP，它的推广位也会保留。
广告标 `neverKeep`，接口层保底不会把它补回来（补回一条广告没有意义）。

验证：`node ad-test.js`（8 种接口 goto、7 种含 ad 子串的干扰值、
4 条标题含「广告」的正常视频、3 种 DOM 标记、8 种角标文字、
白名单优先级、保底行为、banner 的 3 种标记与误匹配保护）。

### 硬时长下限（4.24.0）

`CONFIG.minKeepDuration`（默认 **180 秒**）：短于此值一律隐藏。

```js
minKeepDuration: 180,   // 秒；0 = 关闭
```

几个必须知道的行为：

- **排在主题之后、权威媒体豁免之前**。用户要的是长度，不是内容质量，
  所以 `央视军事 45s 短新闻` 也会被删。若希望权威媒体能穿透，
  把这段移到 `OFFICIAL` 检查之后即可。
- **时长未知（0 / 字段缺失）不删**。拿不到时长就当没证据 ——
  否则接口字段一缺失就会把整屏删空。
- **不触发整号拉黑**。用独立的 `shortVideo` 标记，不走 `topic`：
  否则一个正常 UP 发 3 条短视频就会被自动拉黑整号。
- **白名单 / 已关注 / `mode: 'off'` 仍然优先**，用户自己放行的不碰。
- **接口层仍会保底补 `keepAtLeast` 条**（防 B 站首页白屏），
  但 DOM 层不保底，那些卡片到页面层依旧会被隐藏 —— 最终看不到。

#### 时长抓不到 = 静默漏网（4.25.0）

阈值写对了不等于规则生效。4.24.0 上线后仍有 <3 分钟的视频没被删，原因是
**时长根本没被抓到**：`d = null` → 走「时长未知，跳过」→ 不删。

三层都修了：

1. **解析器**（`parseDuration`）：原来直接 `split(':')`，一个多余字符就返回 null。
   现在正则从任意位置抓 `h:mm:ss`，支持全角冒号、前后缀、尾随换行；
   同时低位必须 < 60，所以 `2024:10`、`2:60` 不会被误当时长。
2. **卡片取值**（`cardInfo`）：原来只取 `querySelector(DURATION_SEL)` 的第一个匹配。
   `[class*="duration"]` 很宽，第一个可能是空元素或包装容器 —— 解析失败就变成
   「未知」。现在遍历所有候选，取第一个能解析的；全失败时再从卡片文本里找。
3. **卡片定位**（`findCard`）：原来 `hasDur` 只认 class 名，B 站改版后 class 一变，
   整张卡片会被当成「没有时长」而**完全不进扫描** —— 既不隐藏也不进面板。
   现在 class 抓不到时，退一步看文本里有没有时长形状。

**仍然保守的一点**：时长确实未知（卡片显示 `--:--`、字段缺失）时不删。
拿不到时长就当没有证据 —— 否则接口一抖动就会把整屏删空。

`__BLF.explain()` 现在会打印原始时长文本，例如：

```
[BLF] 留  [] TopSelecct | 时长?(原文:--:--) | 影史公认无法复制的五大奇迹神作
```

看到 `时长?` 就是没抓到，`dur` 有值却被放行就要查白名单 / 已关注。

验证：`node duration-test.js`（阈值边界、未知时长、白名单优先级、
档位差异、不拉黑副作用、保底行为、解析器 17 组、卡片抓取 7 组）。

匹配按 `TOPIC_ORDER` 的优先级走（ai / meme / tutor / repost / vulgar 最前），
这样面板里报告的原因是准确的
——「走光瞬间合集，笑死」会显示"低俗"，而不是被"笑死"当成搞笑段子。

每类规则分三级（见 `TOPICS` 常量）：

- **strong**：命中即拦（"彩礼"这类词本身足够专指）
- **weak**：需要同时命中 `weakNeed` 个才算（"分手"也可能是歌名）
- **exempt**：命中则不拦（学术讨论、正经音乐、真运动项目）

> **改规则时注意**：`weak` 必须一词一正则。写成 `/分手|复合|前任/` 只会算
> **1 个**命中，`weakNeed: 2` 永远达不到 —— 这个 bug 实际踩过。

设计取向是**宁可漏一点，也不把正常内容大词一网打尽**：

- "拳击基础教学" 不拦（exempt 里有拳击/格斗/UFC）
- "《分手快乐》现场版" 不拦（MV/翻唱/歌曲豁免）
- "搞笑诺贝尔奖" 不拦（正经科普，名字带"搞笑"）
- "交通事故责任认定标准解读" 不拦（法规解读，不是猎奇）
- "沙雕动画是怎么做出来的" 不拦（创作教程，不是搞笑内容本身）
- "女子落水，外卖小哥跳水救人" 不拦（真实施救新闻，不是群体指责）

### 性别群体断言（4.11.0 / 4.12.0）

「女子落水没男人敢救」这类标题：拿一个个例给整个性别定罪，再配一句道德说教。
识别的不是「男人 / 女人」这两个词，而是**群体化的断言结构**：

- **缺失断言**：否定词 + 性别群体 + 意愿动词。
  `没男人敢救`、`竟没一个男人敢下水`、`没有女生愿意站出来`。
  三者缺一不可 —— 所以「女子落水，外卖小哥跳水救人」这种真实施救新闻不会被碰到。
- **群体定性**：性别群体 + `都/全/个个` + 写死的负面词表。
  `男人都没担当`、`男生都装看不见`、`男人都靠不住`。
  负面词表必须写死，`女生都喜欢的秋冬穿搭` 这种正常描述不得命中。

#### 伪新闻式性别猎奇（4.12.0）

「欧盟要求组建全女社会」这一类：拿一个外部权威，配一个性别排他的荒谬政策，

- **人类命运叙事**：世界 / 未来 / 人类社会 + `由女性主导`。
  「这个行业由女性主导」是产业描述，不命中。

### AI 内容（4.10.0）

#### 为什么不能直接收「牢」字

| 会被误杀的 | 属于 |

| 地牢 / 地牢围攻 | 游戏 |

| 套牢 / 解套 | 财经 |


#### 一个实现上的坑

省掉之后，消费部分必须**从字符串开头**就命中钩子 —— 而标题开头是国家词，
永远匹配不上。我改完后测试全绿变全红，就是这个原因。

试过用变长 lookbehind 把匹配起点挪到钩子处（这样面板只显示钩子本身），
V8 下不生效，已放弃。现在的代价是面板里显示的原因等于整个标题，
与标题行重复一次。功能正确，只是略啰嗦。

### 弄坏搜索框的那个 bug（4.42.0）

如果你遇到过「B 站主页点搜索框，什么都不出现」，那是这个脚本造成的。已修。

根因在广告判定的选择器：

```js
// 错的
'[class*="--ad"]'
```

它匹配的是**任何含 `--ad` 子串的类名**，而不只是以 `--ad` 结尾的广告类：

```
search-panel--advance        ← 含 --ad
bili-header__search--advanced
nav-search--adjust
x--admin
```

事故链：

1. B 站搜索下拉里有视频推荐，带 `a[href*="/video/BV"]`
2. `scan()` 把面板收进卡片集
3. `cardIsAd()` 因面板容器带 `--advance` 命中 `--ad`，判为广告
4. `hideCard()` 给它设了 `display: none !important`
5. **B 站复用同一个 DOM 节点**，inline 样式不会自己消失

于是点一次搜索框，面板就永久消失。

**三道修复：**

1. **精确匹配**。`AD_CLASS_RE = /(?:^|\s)[\w-]*--ad(?:\s|$)/`，
   只认「整个 token 以 `--ad` 结尾」。`bili-video-card__info--ad` 仍命中，
   `--advance` / `--adjust` / `--admin` 不再命中。
2. **搜索区域守卫**。`hideCard()` 开头先问 `isSearchArea()`：
   目标含 `input.nav-search-input` / `input[type="search"]` /
   `.search-panel` / `[class*="search-panel"]` 等任一，一律拒绝隐藏。
   主判据用 `input` —— class 会改版，搜索框一定是 input。
3. **启动自愈**。`repairSearchArea()` 在 `bootDom()` 里跑一次，
   扫描带 `data-blf-hidden` 的元素，属于搜索区域的就地恢复。

**以后加广告类选择器时记住**：CSS 属性选择器没有词边界，
`[class*="--ad"]` 和 `[class*="ad"]` 一样危险 —— 后者会咬
`download` / `loading` / `badge` / `header`。要么用完整类名，
要么像现在这样写正则校验 token 边界。

**自查方法**（浏览器控制台）：

```js
__BLF.adCheck(document.querySelector('.search-panel'))
// { isAd: false, isSearchArea: true }   ← 正常

__BLF.repairSearch()   // 手动恢复被误隐藏的区域，返回恢复数量
```

`search-guard-test.js` 守着这几条（14 条断言，自带选择器引擎）。
反向验证过：把 `AD_CLASS_RE` 改回 `/--ad/`，其中 4 条立刻变红。

### 一个不报错的坑：开关漏写 = 整类静默失效

加这个类别时实际踩到了：编辑 `CONFIG.topics` 时把 `rankBait: true` 整行
**替掉**了，而不是在其后插入。后果是「锐评排名」整类当场死掉，
13 条断言变 MISS，但**脚本本身语法正常、不报错**。

根因在 `matchTopic` 的这一行：

```js
if (!CONFIG.topics[key]) continue;   // 开关缺失 = 跳过，不抛错
```

两处都写了才生效：`TOPICS` 定规则，`CONFIG.topics` 上开关。少一处就静默失效。

现在 `topic-test.js` 末尾有一条守护断言，校对两边的键集完全一致，
并区分两种错误：

- **TOPICS 有但 CONFIG 没有** —— 整类失效（实际踩到的就是这种）
- **CONFIG 有但 TOPICS 没有** —— 死开关，写了不起作用

`__BLF.topics` 为这条断言暴露规则表本体。

### 成功学话术（4.6.0）

「身处顶尖 0.01% 的人群，我发现他们想的和普通人完全不一样」这类内容，
卖点是“我掌握了你不知道的阶层真相”，信息量为零且不可证伪。

**这条漏网比前两条更值得说**，因为它暴露了一个反向漏洞：

```js
// 4.5.0 的学术词表
/防御|机制|原理|效应|规律|…|认知|…|逻辑|…|本质|边界|…/.test(t) → neg -= 2
```

`认知 / 逻辑 / 本质 / 边界` 被当成“学术词”给 −2 分。但这四个词营销号用得

汉语里「婚」只有婚姻一个义项，没有跨词风险，
所以单字一次性盖完：结婚 / 离婚 / 婚姻 / 婚礼 / 婚纱 / 婚庆 /
婚介 / 征婚 / 婚检 / 婚房 / 不婚 / 逼婚 / 再婚 / 冥婚 / 婚变……

**同时删掉了两条豁免**：

- `/电影|剧集|影评|纪录片|短片|动画/`
- `/社会学|人口学|经济学|人类学|人口统计|婚姻登记|调研报告|数据分析|研究报告/`

不删掉它们，婚恋题材换个皮就溜过去了：「【纪录片】婚恋市场的经济学」
「婚姻登记数据十年变化」都是。用户的偏好是**题材全不看**，
新闻 / 数据 / 学术 / 纪录片不是豁免理由。

保住的东西：

- 「《分手快乐》梁静茹 现场版」—— 音乐豁免留着，且只命中 1 个 weak，不拦
- 「电影《前任3》影评」—— 同上，weak 不够 2 个
- 「恋爱心理学：依恋类型如何影响亲密关系」—— 不含「婚」
- 「单身经济崛起」—— 单身不是婚姻状态的主题叙事，不拦

代价要说清楚：**「离婚律师的收入」「结婚证丢了怎么补办」这类也会被拦**。
这是单字判据的必然结果 —— 它认的是字，不是意图。若只想要窄一点的
口径，把 `/婚/` 换回列举式即可。

> **设计上的根本局限**：现在是**黑名单式**的 —— 一个话题一个话题地加。
> 你每次发现一条漏网，就意味着还有 N 个没被覆盖的类别在漏。
> 已知完全没覆盖的：职场叙事、育儿、颜值穿搭、减肥、装修、心理测试、
> 生活方式、明星动态、军事时政、探店。详见 README 末尾。


### 正则审查与跨词咬字（4.8.0）

一次独立正则审查用脚本自己的 `matchTopic()` 实测了 49 条知识标题，
**47 条被误杀**。原因几乎全是中文不分词的咬字：

```
小三和弦为什么这么忧伤       → 小三（乐理）
绿茶的正确冲泡方法           → 绿茶（茶）
核裂变为什么能释放能量       → 裂变（核物理）
两性物质为什么能和酸碱反应    → 两性×2（化学）
音叉共振实验：频率与振动      → 频率×3（声学）
MySQL索引的底层逻辑          → 底层逻辑（技术写作）
华山长空栈道天梯             → 天梯（地形）
中国考试制度的历史演变       → 国考（历史）
老公考虑换工作               → 公考（日常）
CS2（二硫化碳）的毒性        → CS2（化学）
```

主题命中是 **hard 拦截**——早于时长判定，`KNOWLEDGE` 的 −3 完全不参与，
所以每一条都是**永久误杀**，只能手动点 ✅ 救回。这比漏网严重得多。

修法分三类：

1. **裸露的 1–2 字词全部加上语境限定**：
   `小三(?!和弦|度|阳)`、`擦边(?:视频|直播|写真)`、`裂变(?:营销|增长)`、
   `相撞` 用 lookbehind 排除粒子/分子/原子/天体、`国考(?![古试生])` 且前置也要边界。
2. **从 strong 降到 weak，或直接删掉**：
   `天梯 / 上分 / 上段 / 赛季 / 段位 / 新赛季 / 公测` 在体育、软件、地理里都常用，
   不是游戏证据；`根治 / 真相 / 杀死癌细胞 / 上火` 是医学与文献的常用词。
3. **给 `exempt` 补配套**：考古/墓葬/文物、建筑史、盲区、货车司机、
   心理测量、烹饪、劳动法、政策解读。

**另一个反向缺陷**：`weak` 里同一个词不能出现两次。
`天梯` 曾同时写在两条正则里，于是「华山长空栈道天梯」被算成 **2 个命中**，
直接越过 `weakNeed=2`。这与「`weak` 必须一词一正则」是同一条约定的两个方向，
`bite-test.js` 现在会扫描并断言无重复。

**营销词分级**：`揭秘 / 震惊 / 盘点` 一票否决知识保护；
`真相 / 尘封 / 绝唱` 在学术锤点（考古/文献/史料/论文）在场时只算 +1。
否则「考古发现的真相：二里头是不是夏都」会被当成大字报。

## 从接口层到页面层的优先级

两层必须给出相同的结论，否则会出现「点了 ⛔ 却还在」「点了 ✅ 却被隐藏」。

优先级统一为：**已关注 → 白名单 → 黑名单 → 主题 → 质量分**。

- `is_followed` 只有接口层拿得到，DOM 层的 `cardInfo()` 没有这个字段。
  所以接口层把见到的已关注 mid 记进 `followedMids`，DOM 层查这个集合。
  不补的话，关注的 UP 发了主题内容 → 接口放行 → 卡片渲染 → `judgeCard` 命中主题 → 被隐藏。
- `store.add()` 与 `allow.add()` 现在**双向互斥**。早先只有后者清前者，
  两边同时存在时接口层放行、DOM 层隐藏，表现为「⛔ 好像没生效，刷新又回来」。

## 空页自愈的正确做法

「整屏被拦干净」有两种完全不同的成因，必须区别对待：

- **判定故障**（选择器错位、规则 bug 把正常内容也当成垃圾）→ 撤销隐藏 + 60 秒降级。
- **用户就是要全拦**（一屏全是游戏/成功学，推荐流有聚集性）→ 保持清空，只放回 1 条软的。

判据：被隐藏的卡片里有没有硬判定（主题命中 / 黑名单）。
旧版一律走第一种，于是「拦干净了」被当成「脚本坏了」，全量恢复 + `degraded` 永久关闭过滤。
**这是「明明装了脚本却还满屏垃圾」的主因。**

配套三个修复：

- `recoverIfEmpty()` 的调用条件原本是 `if (!root)`，而 `bootDom` 和定时器都传 `scan(document)`，
  所以它**从未执行过** —— 死代码。现在判 `isFullScan`。
- 自愈放回的卡片打 `blfKeepOnPurpose` 标记，`scan` 跳过它。
  否则下一轮又判 hide，卡片每 2 秒闪一次。
- `keepAtLeast` 保底只对接口层生效，且**允许补回主题命中**（但绝不补回黑名单）。
  接口层返回空数组会让首页直接空白，比看到两条游戏视频糟得多；
  DOM 层不受影响，可以保持整屏清空。

### 设问式营销体（4.9.0）

「为什么很多外贸要求只招女生」这类标题的量产模板：**为什么 + 人的群体 + 泛化断言**。
设问制造悬念，内容是无法核查的泛化议论。

难点在于不能把所有「为什么」都拦掉 —— 4.2.0 起有一条 `现象解释` 的 −3 保护，
专门救「为什么超市里很少见到鹅肉」这种正经科普。全部拦掉等于退回旧版本。

**真正的区别是问的对象**：

- 营销体问**人的行为**：为什么**年轻人**都存不下钱 / 为什么**大家**都爱熬夜
- 科普问**物的属性**：为什么天空是蓝色的 / 为什么指南针指向北方

后者主语不是人的群体，所以不会被命中。实测 14 条天文/物理/工程科普 **0 误伤**。

两类规则：

1. **`whyBait` 类**：`为什么 + 人的群体词 + 都/总是/越来越/却/一…就`。
   群体词是白名单式枚举（年轻人/中年人/男生/女生/国人/大家/人们/老板/父母/打工人…），
   所以「为什么**月亮**总是同一面朝向我们」不会命中。
2. **`career` 类补招聘歧视规则**：`只招/不招/都要求 + 女生/35岁/应届`、
   `公司/HR/招聘 + 不要/歧视`、`外贸/工厂/奶茶店 + 只招`。
   限定动词，不会咬到「招财猫」。

**必须保住的**（`exempt`）：人口学 / 社会学 / 统计学 / 实证研究、
数据 / 报告 / 综述，以及自然工程锚点（瑞利/浮力/密度/热力学/折射/共振/量子…）。
「为什么年轻人不结婚了：一份人口学报告」「为什么现代人普遍焦虑：社会学视角」都留着。

> 判据总结：**有可核查的对象（物、数据、研究）就是知识；
> 只有泛化的人与情绪就是营销号。**

### 现象议论体（4.18.0）

「年轻人集体养大肥鱼，一场爱压抑的自救」这类：把一件小事 / 一个热点
包装成时代症候。前半句陈述“大家都在做某事”，后半句用升华词收尾。
内容无法核查，信息量全在语感上。

与设问式营销体是同一个东西的两种句式：

- `whyBait`：为什么 + 群体 + 都/总是…（设问句）
- `socialTake`：群体 + 集体化 + ，一场…的 X（陈述句）

三个条件**缺一不可**：

1. 群体主语：年轻人 / 当代青年 / 这届年轻人 / 打工人 / 普通人 / 现代人 /
   都市青年 / 成年人 / 中年人 / 大学生 / 全民 / 全网
2. 集体化动作：集体 / 都在 / 纷纷 / 扎堆 / 一窝蜂 / 全在
3. 升华式收尾：`一场…的` + 自救 / 溃败 / 革命 / 觉醒 / 逃离 / 反击 / 反抗 /
   崩塌 / 狂欢 / 困局 / 症候 / 突围 / 沦陷 / 溃逃 / 出走 / 出口

所以「年轻人集体考研，一份就业分析报告」不会命中 —— 后半句是“报告”，不是“自救”。
关键在于**不靠具体热点词**：蹭 DeepSeek 的换成蹭别的，规则不用跟着改。

边界样本（必须留）：

- 「当代青年集体躺平背后的社会学分析」留（exempt 认社会学）
- 「打工人集体维权，法院判决结果公布」留（集体行动是法律事实）
- 「年轻人集体租房，公积金政策解读」留（政策解读）
- 「打工人纷纷返乡，一场春运行程记录」留（行程记录不是升华）
- 「成年人学钢琴，从零开始的练习计划」留（无集体化动作）

### 外国人爽文（4.3.0）

「老外被中国震撼」是搬运号最稳定的模板：外籍身份 + 中国对象 + 强烈情绪反应，
信息量为零。这类不靠文案打分，走**主题屏蔽**直接整类关掉。

判定要求三类信号**同时出现**，顺序不限：

- 身份：老外 / 外国人 / 外国网友 / 留学生 / 美国 / 日本 / 韩国 / 德国 …
- 对象：中国 / 中华 / 国产 / 中餐 / 高铁 / 故宫 / 中医 / 汉字 / 兵马俑 …
- 情绪：后背发凉 / 头皮发麻 / 震惊 / 傻眼 / 全程沉默 / 破防 / 泪目 / 跪了 /
  直呼不敢相信 / 心服口服 / 肃然起敬 / 自愧不如 / 害怕 …

单有"老外"或单有"震惊"都不拦 —— 真正的外国人生活 vlog 不这么写标题。
学术研究、纪录片、外交部口径和政策类内容有豁免：

- 「美国人眼中的中国历史：一份研究综述」留
- 「纪录片：外国学者如何研究中国史」留
- 「留学生签证政策最新变化解读」留
- 「我在中国生活十年，回国后反而不适应」留

指纹层另有兜底：情绪爆点 + 无栏目标记 + 递进句式（"越读越…"）会加分，
即使标题没写国别也能抓住，比如
「读中国史书读到后背发凉，越读越不敢往下看」。标题里堆 3 个以上话题标签
（`#中国历史 #历史` 这种同义重复）也算一个弱营销信号。

### 分数封顶与知识保护（4.2.0 起）

结构类信号（标题长度、逗号数量、句末标点、口语叙述、无栏目标记长句）是**同一个现象的
多个侧面，不是独立证据**。无上限累加会让正经科普拿到荒谬的高分：

> 「为什么超市里很少见到鹅肉？鹅非常好养，吃草就行，还能产鹅绒，但为什么越来越少了？」
> 结构分累加到 10 —— 而这是一条完全正常的科普。

所以现在 **结构分封顶 `STRUCT_CAP = 3`**，语义分（营销词、价格锚点、空洞升华…）不封顶。

配套加了两条知识保护：

- `KNOWLEDGE` 词表命中 −3（生物/物理/数学/历史/音乐/摄影/模组…）
- 现象解释疑问句 −3（"为什么…很少/越来越多/越来越贵"这类客观疑问）
- 但命中**强营销词**（盘点/震惊/揭秘/真相/内幕）时，知识保护失效 ——
  否则「盘点那些差点成功建造的反人类工程」会被"工程"洗白

**4.3.0 补的漏洞**：知识词在**情绪爆点**面前也失效。原先
「一个美国学生读中国史书，越读越后背发凉」里的"历史"直接给了 −3，
整条标题以 −2 分安全落地 —— 题材词成了历史叙事营销号的免死金牌。
现在标题出现「后背发凉 / 头皮发麻 / 破防 / 泪目 / 跪了 / 肃然起敬…」
这类反应描写时，知识词不再减分：卖点是情绪，不是知识。

实测：240 条实时推荐里，质量误杀从 32 条降到 18 条，
救回 12 条正常内容（游戏、美食、摄影、乐理、体育、科普）。

### 质量过滤

单条视频由 `decide(时长, 标题)` 判定，页面层和接口层共用同一套规则。

**先过时长门坎（4.24.0）**：`d < minKeepDuration`（默认 180 秒）直接隐藏，
不进指纹层。这条排在主题之后、权威豁免之前 —— 是用户的长度偏好，
不是对内容的判断。详见下面的「硬时长下限」一节。

**核心：`marketingFingerprint()` 打分，按阈值拦截**

指纹门槛按长度分层：

- **短于 120 秒**：`fp >= 2`
- **2–10 分钟**：`fp >= 3`
- **10 分钟以上**：`fp >= 4`

> 注：4.24.0 起 180 秒以下的视频已经先被硬时长下限砍掉，
> 上面的短阈值只对 180 秒以上的视频生效。

**加分项（大字报特征）**

- 语义类：营销词（震惊/盘点/不为人知…）、价格锚点、空洞升华（三观/格局/正能量）、
  引导互动（收藏/点赞关注/评论区）、标题党标点、省略号堆叠、年份+长标题、悬念词
- 结构类：无栏目标记的长句（+2）、口语叙述、多短句、句末标点

**减分项（正常内容特征）**

- 栏目/系列标记：`【】`、`｜`、`#话题`、`MV/PV/OP/ED`、`第N集`、`P3`、`《作品名》`
- 内容类型词：攻略/实况/教程/讲解/评测/拆解/精讲/复盘/测评/开箱/合集/纪录片/花絮/混剪/手书/翻唱
- 英文专名（`Rust`/`Minecraft`/`RTX`…；`AI`/`NPC`/`MV` 等通用缩写除外）
- 学术词（防御/机制/原理/效应/模型/算法/认知/哲学/逻辑…）

**权威媒体白名单**：新华社 / 央视新闻 / 央视军事 / 人民日报 / 中国军号 等，
精确匹配整个 UP 名（避免「央视视角」这类蹭名字的号）；短线拦截从未触发过的接口层
永远不走这里的规则。

**优先级**（从高到低）：已关注 → 用户白名单 → 用户黑名单 → **主题屏蔽** → 时长/文案规则

主题命中的条目算「硬拦截」，不会被 `keepAtLeast` 保底机制补回 —— 用户明确说了不看。

**UP 主维度**：某 UP 连续产出 2 条带强营销信号（营销词 / 价格锚点）的内容，
自动整号拉黑。这是对付「换一换又冒出来」最有效的一招 —— 屏蔽的是账号，不是单条视频。

## 改代码后怎么部署

```bash
./deploy.sh
```

然后在自动打开的 Tampermonkey 页面点一下 **Update**。

**为什么不能全自动**：Tampermonkey 把脚本存在 Chrome 的 LevelDB 里，Chrome 每次启动都会
把旧 log 合并进压缩的 SSTable。实测过三种外部写入方式（追加活跃 log、改 MANIFEST、
整体重建库）：要么"写成功但加载旧版"，要么被扩展在下次启动时用自己缓存的那份覆盖回去。
唯一稳定的路径是它自己的安装流程，需要点一次确认。

`backup/tm-settings-221415` 是健康库基线，**别删**，回滚时直接复制回去。

### 隐藏卡片时选错容器（踩过的坑，会清空首页）

`CARD_SEL` 里的 class 名会随 B 站改版变化，有些 class 既用于单张卡片，
也用于**整个列表容器**。容器能 `querySelector` 到子卡片的标题，于是：

1. `scan()` 把容器当成卡片收进来
2. `cardInfo()` 从容器里读到某张子卡片的标题
3. 该标题被判死 → `hideCard()` 隐藏整个容器 → **首页一条不剩**

实测出现过：扫描 336 条、拦 51 条，页面全白。

现在有三重保护：

- `MAX_LINKS_PER_CARD = 3`：一个卡片不该含超过 3 个视频链接，多了就是容器
- `findCard()` 遇到超标元素直接 break，`scan()` 过滤掉超标元素
- `hideCard()` 拒绝隐藏超标元素
- 兜底：`recoverIfEmpty()` 每次全量扫描后检查，**如果一张可见卡片都没有，
  撤销所有隐藏并进入降级模式**（只记录、不再自动隐藏，徽章变红提示）

`dom-test.js` 守着这几条，别让它们被改回去。

### 编码（踩过的坑）

`serve.py` 必须返回 `Content-Type: text/javascript; charset=utf-8`。缺了 `charset`，
Tampermonkey 会按 Latin-1 解码，脚本里所有中文注释和**中文字符串**都变成
`æ¡£ä½` 这种乱码。

这不是显示问题：判定规则里全是中文正则（`/震惊|盘点|揭秘/`），一旦编码错，
中文匹配会全部失效，过滤直接瘫痪而没有任何报错。

`deploy.sh` 已内置自检：响应头不含 `charset=utf-8`，或下载内容不是合法 UTF-8、
或检不出 `档位`/`震惊` 等关键词，就直接报错退出，不会打开安装页。

## 调参

改 `bilibili-filter.user.js` 顶部的 `CONFIG`，然后 `./deploy.sh`：

- `mode`：`off` / `light` / `balanced` / `aggressive`
- `aggressiveMax`：短视频门槛，默认 120 秒
- `shortFpThreshold`：短视频指纹阈值，默认 2
- `fpThreshold`：2–10 分钟的阈值，默认 3
- `fpLongThreshold`：10 分钟以上的阈值，默认 4
- `keepAtLeast`：保底保留条数，默认 2（所有档位生效，防止首页刷空）
- `showBadge`：右下角徽章

想更狠：把三个 fp 阈值各减 1。想更保守：各加 1。

## 已知修过的跨词误匹配

中文没有分词，短词正则会咬到别的词里。目前已发现并修掉：

- `/国考/` 命中「中**国考**古」→ 三星堆、墓葬发掘这类内容被当成公考培训。
  改为 `/国考(?!古)/`，测试里守着 `中国考古学百年` 与 `国考报名人数创新高` 两条。
- `weak` 写成 `/分手|复合|前任/` 只算 1 个命中（上面提过）。

加新规则时留意这个坑：优先用带边界的写法，别让两字词裸奔。

## 已知没覆盖的类别（黑名单模式的固有局限）

脚本靠**一个话题一个话题地加规则**工作。每发现一条漏网，就说明还有别的类别
在漏 —— 这是结构问题，不是某条规则没写好。

### 一个硬约束：拿不到分区信息

首页推荐接口（`/x/web-interface/wbi/index/top/feed/rcmd`）返回的字段里
**没有分区名**（无 `tname`），`rcmd_reason` 也常为 null。实测 `fixtures/rcmd-sample.json`
的 20 条真实返回，全部如此。

所以没法做「只留知识区 / 科技区 / 人文历史区」这种白名单 ——
**标题、时长、UP 主是唯一可用的信号**。这是硬约束，不是实现选择。

### 两条路

1. **继续加黑名单类目** —— 直接、可控，但永远滞后一步，且每加一类都要配
   exempt 兜住正经内容（「装修」要留「建筑史」，「减肥」要留「营养学」，
   「育儿」要留「发展心理学」）。
2. **改成白名单** —— 只保留命中知识信号的内容，其余全砍。一次解决，
   但会连带砍掉纯音乐、Vlog、纪录片预告这类放松内容，且误伤代价更高。

目前是路线 1，因为误伤代价高于漏网代价。
